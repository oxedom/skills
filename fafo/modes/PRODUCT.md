# Product research

Reconstruct what the application does and how people use it. Aim for an explanation useful to someone planning, building, or evaluating a similar product.

## Questions to answer

- What is the product, who is it for, and what outcome does it help them achieve?
- What are its main features and how do they fit into a typical user journey?
- What information does it work with, and how do its main business entities relate?
- Which roles, plans, quotas, payments, or feature gates shape the experience?

Use interface text, navigation, forms, actions, data requests, and business rules as evidence. Go beyond listing feature names: reconstruct what a user can actually do.

For each important feature, explain what starts it, what the user supplies, what happens next, and what result is produced. Include meaningful validation, limits, permissions, or branching behavior when visible. Connect related features into workflows such as onboarding, creating something, collaborating, and reaching an outcome.

## Shape the report

Start with a plain-language product overview, then describe the main workflows and features. Include business entities, user roles, and monetization when supported by evidence. Give the most space to the features that define the product.

Support important claims with source references. Label uncertain reconstructions. A pricing string does not establish a current price; a feature flag does not establish availability; missing evidence does not establish that a feature is absent.
